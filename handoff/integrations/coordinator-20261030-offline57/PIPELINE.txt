BC2 weapon pipeline: what exists and what it proves
Updated October 31, 2026. Root coordinates this run; agents own disjoint runtime files.

There is working batch asset/profile tooling. There is NOT yet an established
all-weapons working reload implementation. Prior enrollment counts overstated
practical completion when described as finished weapons.
The workflow uses separate scripts and runtime adapters, coordinated manually.
It does not automatically establish that every enrolled weapon works in VR.

1. Identify exact weapon configurations and their source assets
   tools/bc2_firearm_magazine_batch.py
   tools/bc2_weapon_animation_pipeline.py
   handoff/tasks/WEAPONS/20261030-roster43/roster.json
   These read source identities, skeletons, clips, geometry and equipment families.
   Existing roster: 77 names / 181 configurations. Do not repeat enrollment.

2. Generate tables and connect them to the normal build
   profiles/weapons43/Enrollment.cmake
   profiles/weapons45-magazines/Enrollment.cmake
   profiles/mechanism-family41/Enrollment.cmake
   These select generated support, magazine, shotgun, bolt, feed, slide and muzzle
   definitions. Source routes: 128 magazine, 25 shell/pump, 24 feed, 4 clip/cylinder.
   Table inclusion proves configuration coverage, not successful live interaction.

   Family                Configurations   Current connection/check
   Detachable magazine   128              Production raw-contact chain checked
   Shell/pump             25              Independent tube path wired; source checked
   Feed mechanism         24              Native dispatch/completion checked
   Clip/cylinder           4              Separate fixed-container route
   These are source routes, not a list of headset-confirmed working weapons.

3. Produce real hand/weapon contact from the running game
   src/games/bc2/Bc2RigPublication.cpp
   src/games/bc2/Bc2MagazinePresentation.cpp
   src/games/bc2/Bc2Gameplay.cpp
   Native owner, selected weapon, palette, hand pose and original input lifetime
   must agree. A table entry cannot make missing/rejected live contact valid.

4. Run the physical reload and keep its ammunition/mechanical state
   src/games/bc2/Bc2MagazinePhysicalReload.cpp
   src/games/bc2/Bc2PhysicalFeed.cpp
   src/games/bc2/Bc2PhysicalReload.cpp (tube/shell, independent of magazine path)
   src/games/bc2/Bc2ReloadFlowRuntime.cpp
   This is the runtime connection being repaired. It must start from actual
   contact, suppress conflicting stock actions, dispatch the native operation
   once, and accept the matching result without losing rounds or owed cycles.

5. Check the connection, build, install and test in headset
   tests/Bc2MagazineRawContactPipelineTests.cpp
   tests/Bc2ReloadFamilyDispatchTests.cpp
   tests/Bc2HeldFireCadenceTests.cpp
   handoff/integrations/coordinator-20261030-offline57/Run-Focused.ps1
   Build.ps1 (required normal x86/x64 builds)
   Old component tests supplied valid raw input directly. The new magazine check
   goes through the production palette reader, publication admission, contact
   builder and physical consumer instead. It samples 178 selected asset bindings;
   that count differs from the reload-family roster and is not a success count.
