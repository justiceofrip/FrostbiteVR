# Fixed container and clip reload policy

Source implementation prepared; deterministic tests have not been compiled or run by this agent. No native/game/headset qualification. Root owns builds and native adapters.

`FixedContainerReload` retains a cylinder's open -> eject spent -> insert -> close sequence. Opening, ejection and closure require measured hand motion; ejection does not erase live rounds. Closing before capacity preserves partial loading. `EnBlocClip` performs a measured insertion and one bounded transfer, retaining existing loaded rounds under explicit mod top-up policy. Neither mode adds a chamber or manual bolt cycle. Tracking loss/stow interrupts hand authority but retains physical debt and pending native work.

The policy uses `FeedInteraction` for measured motion and typed `FeedPhysicalCompletion`/`FeedReloadRequest` for identity. Its internal feed projection is only a recognizer implementation detail. It is not belt evidence, a native observation, or a second `FeedAmmunition` store. The caller supplies the existing stable-weapon `AmmunitionLedger`; `InsertRounds` was added there with a backward-compatible final `Queue` argument. Transfer is `min(requested, capacity-loaded, reserve)`; nonpositive requests fail.
