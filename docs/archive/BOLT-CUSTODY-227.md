# Configurable hands and bolt custody replay

This candidate adds an immutable `WeaponCycleHandAssignment` to `WeaponCycleProfile`, defaults to left mechanism/right gun, and updates the actual WeaponCycle and PhysicalWeaponCycle role checks, claim acquisition, regrip and renderer targets to honor it. Same-hand or invalid assignments reject. `CurrentPhysicalWeaponCycleTarget` accepts an explicit expected assignment, defaulting to the previous layout; a right-mechanism target therefore cannot pass a legacy left-mechanism renderer by accident.

The baseline is the pump agent's frozen **pump226-gameplay-candidate** headers, including its original historical contact evidence and retained ready reconciliation. Apply this candidate after those changes, with the atomic HandInteraction custody API from `handedness-payload`. No source in the main repo, native adapter, rig or installed game was modified.

## BoltWeaponCustody

The separate shared coordinator drives the real PhysicalWeaponCycle and HandInteraction implementations:

1. `Arm(profile, heldLease, contactFromMechanismWrist, now)` records the exact held cycle and contact calibration. The test profile selects right mechanism/left gun. This is a portable gesture contract, not native weapon admission.
2. `EnterCustody(current, transfer, weaponInWorld, receivingWristInWorld, hands)` accepts only the original gun + its other-hand WeaponSupport and an atomic transfer to the designated gun hand with no companion claim. RightGun + LeftSupport becomes LeftGun + RightEmpty. This must happen before the ordinary arbiter Update processes the old right gun release.
3. `Update(sample, hands)` renews the current custody gun from explicit current proof. It converts the original mechanism wrist pose back to the calibrated contact frame, then passes the real packet/contact source into PhysicalWeaponCycle. A genuine neutral/grip sequence is required. Unlock, retract, advance and lock remain the shared ordered gesture policy; no support transfer shortcut is supplied by this coordinator.
4. At physical submission the mechanism claim is released once, while LeftGun remains. `ReturnCustody` requires a neutral packet strictly after submission followed by a fresh grip/contact for the original gun contact. It atomically obtains RightGun + LeftSupport. It cannot acknowledge the pending native outcome.
5. `ObserveReady` and `ReconcileReady` forward only the exact completion to PhysicalWeaponCycle. The coordinator's `blocksFire` remains true until custody has returned, the native outcome is complete and a valid current GunHold is renewed.

While the left hand holds the gun, a captured weapon-to-wrist attachment produces the weapon target from the left wrist only. Right bolt movement cannot drag the whole weapon. Return captures a right-wrist attachment at the same weapon pose, avoiding a pose jump. `CurrentBoltCustodyWeaponTarget` checks the current exact gun token, owner, sequence, time window, tracking/release state and rigid pose before a renderer uses the result. A real adapter still must validate native rig/part identity and publish all claims/targets together.

Tracking/focus/lease loss is fail-closed. The coordinator does not recreate a lost GunHold, forge a neutral packet, infer rejection from timeout, discard an ambiguous native request, or write ammo/native state. A native owner retirement still belongs to the game adapter. A physical interruption while custody remains restarts the full shared gesture after neutral; it does not preserve a partial unlock/stroke. General actor/rig recovery after lost gun custody is outside this candidate.

## Measured inputs and explicit limits

`MeasuredBoltCustodyFixture-v2.h` is generated by `tools/make_bolt_custody_fixture.py` from `bolt-calibration-03.json`, SHA-256 `2443123216b9ba1866a902fc87ea1ba93e919d51e87317ac65c1261664a54bd9`. The generator admits only the exact M24/SV98 named BoltAction rows with their independent jntWpn_3 part and measured complete right wrist/finger contact candidate. It exports six bounded pose landmarks per model, not raw animation curves.

The fixtures use the measured first part pose, largest rotation pose, maximum/minimum translation poses, final dwell pose and right wrist-to-part transform. M24 travel is 75.564669 mm; SV98 is 75.564555 mm. Both measured rotation magnitudes are 1.244276 rad; the gesture uses the measured sign about the weapon-space translation axis. Native authored BoltActionTime is retained as metadata (M24 1.65 s, SV98 1.6 s), distinct from the 1.8 s animation duration.

**The first authored sample is only the offline gesture origin; it is not a verified native closed stop.** The measured right contact comes from a rear contact window. The replay extrapolates that rigid grasp to the other measured landmarks as an emulated controller motion; it does not claim the authored wrist stayed attached throughout the original clip. Intermediate poses and 10 ms input cadence are generated for the controller replay. The 2 mm endpoint tolerance, 20 mrad angular tolerance, 50 ms dwell, contact/lateral/step limits and 10 s timeout are explicit test-policy choices, not extracted native bounds or calibrated controller thresholds. Both fixture flags `NativeHandleVerified` and `NativeClosedVerified` remain false. No runtime profile is registered or admitted.

M95 still lacks the expected part track; GOL still fails strict right-hand contact stability. Neither is silently substituted into these tests. The exact native sniper handle/active pose correspondence, semantic stops, wrist/controller alignment and live rig custody path remain necessary before enabling right-hand bolt operation in BC2.

## Validation and integration

`Build.ps1 -Architecture x86` and `-Architecture x64` pass with MSVC C++20 `/W4 /WX /permissive-`. Each runs eight coordinator groups, including 48 full repeated measured-pose cycles, all 21 frozen pump226 PhysicalWeaponCycle groups and all 13 canonical WeaponCycle groups. Tests exercise ordered stroke rejection, release/regrip, immutable N-1 right-hand geometry with current left-gun proof, fixed left attachment, current renderer receipt checks, failed handoff/return, tracking loss, duplicate dwell packets, one native release, exact late completion, and repeated gun return/rearm.
