# Physical pump consumer candidate — 222

The shared `PhysicalWeaponCycle` now runs the existing pump/bolt recognizer with
the actual `HandInteraction` arbiter. It transfers an explicitly supplied current
support claim into a mechanism claim, or acquires on a neutral/press edge with
fresh original contact. It renews only its own claim. A short stroke cannot
release the native cycle. Rear and front endpoints require distinct samples and
dwell. The consumer emits one immutable native release request after the complete
gesture and keeps fire blocked until an exact native-ready receipt.

Physical interruption clears presentation and releases only the owned mechanism
claim. Focus/tracking loss, grip release, discontinuity or a lost gun claim may
restart the entire gesture after a new neutral packet under the same freshly
observed native held cycle. Recovery preserves the original transaction deadline.
Owner/space changes, native evidence loss and native rejection cannot rearm it.
After submission, physical interruption preserves the pending native transaction;
the hand is free and no new release is emitted. Timeout remains fire-blocking and
cannot admit another cycle until the adapter proves rejection/non-dispatch.

The renderer target has independent original input/native/claim bounds. Physical
hand claims use the controller packet lifetime, while presentation remains capped
by the native held view. `BuildSpasPumpCyclePart` validates this shared target and
the exact current claims before calling the existing one-leaf private palette
planner. It enforces the measured 0.09495844 m SPAS stroke and explicitly supplied
signed axis. It preserves the closed part transform and ordinary native source
bytes. It cannot derive a closed boundary, grip socket or sign from extrema.

## Verification

MSVC `/W4 /WX`, x86 and x64 each pass 13 existing recognizer groups, 17 new
physical-consumer groups and 5 SPAS part groups. These include repeated shots,
support transfer, partial strokes, release/regrip, a physical interruption matrix,
ownership/space retirement, exact completion/rejection, pending interruption,
timeout ambiguity, short native views, duplicate packets, stale claims/targets,
and the full controller-to-private-palette composition. The latter preserves
native palette bytes and checks each generated fore-end translation.

Native held/ready receipts and native boundary calibration are mocked in these
tests. Existing captured extrema still only establish relative SPAS part travel.
No game process, injection, native write, GPU test or headset was used. No enabled
profile or default capability changed. Full normal builds are integration-owner
work after applying this isolated payload.

## Runtime gap

The ordinary BC2 gameplay/native/render callbacks do not yet call this consumer.
The next integration needs a successful-shot identity, a current exact three-copy
pump hold capability, native release/ready receipts, ordinary fire arbitration and
paired hand/part publication. Existing native pump hold is a separate fixed 350 ms
diagnostic; it does not prove sustained player pumping. State-labelled closed
geometry/sign/contact, animation-tail behavior, last-round/empty behavior and
actual-game/HMD acceptance remain unverified.

The portable policy has no engine addresses, native counts, chamber arithmetic or
registration policy. Future adapters must supply their own held/ready authority.
