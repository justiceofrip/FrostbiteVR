# Recovery254: predicted-shot rollback and replay

Actual253 supplied an exact original client Restore that temporarily undid its
tentative shot. The unchanged snapshot bytes restored idle and one round; the
same client then replayed the shot, followed by the independent server shot.
Treating that Restore as an ammunition contradiction cancelled the physical
mechanism before any manual interception began.

The shared cycle service now accepts that narrowly verified pre-interception
transition for its supported nonempty pump/bolt paths. It withdraws only the
affected client's tentative observation. The original physical cycle/shot IDs,
deadline and other copies' evidence stay intact. That client must demonstrate
its own shot again, and all three copies must reach the exact selected boundary
before a mechanism lease can exist. No ammunition, snapshot or native state is
written by this correction. A replay does not create another owed physical action.

trace hash. A service regression failed before the fix and passes after it;
both supported modes and both client branches cover repeated prediction replay.

and rollback after interception remain rejected. Seven focused suites pass on
