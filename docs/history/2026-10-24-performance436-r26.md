# Performance 436 R26: local copy-service timer

R25 startup evidence showed the intended short service could spend 17.5321 ms
in an episode. R26 uses a Host-owned auto-reset high-resolution waitable timer,
created only when the private service is explicitly enabled. It arms a relative
1 ms wait with a 2 ms wait timeout. Create, arm or wait failure disables servicing
without acknowledging or retiring the pending GPU copy. The existing three-poll,
two-wait limit, ownership checks and asynchronous completion path remain.
There is no coarse fallback, busy spin or global timer-policy change. Scheduler
and driver overshoot are measured rather than claimed impossible.

Independent implementation review passed. Focused tests cover timer failures,
single creation/closure and retained Copying ownership followed by normal
completion. One API-only smoke check completed all 16 waits with observed
elapsed times from 1.0169 to 2.763 ms under build load. It has no timing pass
threshold and proves neither an FPS gain nor a hard real-time deadline.

The full x86 build passed 304/304 suites. x64 validation and the actual-game
comparison remain pending at this entry. Native integration source is unchanged
from R25: `100d1f9faf90ec699b230617251d6c3e37a12ac1079e9c999814cc28963683a2`.
The normal runtime remains private and default-off; installed/public 0.1.12 is
unchanged. Latest accepted measurement remains R24's 29.8368 fresh stereo
pairs/s at 2784x3024 per eye and 1x samples, not a campaign-wide headset guarantee.

Private test preparation reuses the original 132 menu checks, reference capture,
reviewed Resume Game selection, actor witness and pacing proof. Only the fixture
DLL with the reviewed 120-second total lifetime needs rebuilding. The intended
comparison uses one new game50/onfoot25 interval against retained R24, with no
repeated baseline or reference capture. Both full normal builds must pass first.
