# R25: bounded host-copy completion service

The R24 result retained roughly 30 fresh stereo pairs/s at 2784x3024 per eye
and actual single-sample depth. Exact ticket joins showed copy completion only
observed on the following host frame, with most consecutive deliveries three
host frames apart. R25 tests earlier observation of actual GPU completion.

The new private `FVR_PRIVATE_HOST_COPY_SERVICE_MS` accepts only 0, 1 or 2;
default 0 performs no new polling, clock reads or sleeps. An enabled episode
retains one exact owner/context/device/ticket/space, observes the existing real
copy query, and cannot admit a successor. The service has at most three polls
and two Sleep(1) calls. Elapsed time includes driver calls and scheduler
overshoot; the requested deadline is not a hard real-time guarantee. Completion
keeps local color/depth images until ordinary presentation. Fault, cancellation
and timeout retain the existing ownership and fallback rules.
