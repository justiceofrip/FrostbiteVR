# SingleFire magazine candidate seam

Handgun magazine integration is closer than belt-fed LMG integration. Existing
LMG work has authored parts/contact and pure FeedMechanism queries; it has no
ordinary cover/latch/feed coordinator or native reload/readiness adapter.
Bc2BeltAmmo is SPAS ammunition-belt presentation, not an LMG belt-feed backend.

MP443 and MP443_sp have exact configuration, selected visibility and authored
slide-motion metadata. Both use wcSmg, SingleFire and rtMagazine, capacity 17,
three magazines, reload 3.75/threshold 0.5 and zero bolt fields. Weapon category
names do not substitute for these fields. Existing strict magazine contact
extraction rejects both; M9 also lacks a valid strict contact window. There is
no slide-stop or authoritative chamber observation in the existing evidence.

New executable piece: the optional descriptor compiler extension accepts an
exact reviewed static-proof document. Installed FireLogicType reflection proves
SingleFire 0, bolt 1 and AutomaticFire 2. Original Update/Step instructions execute
22 MP443-family cases through existing machine emulation: stock 0/51→17/34,
scoped empty inhibition at 1/60 s, 59.622 ms and 100 ms, 8/17-round original remove/return
with zero/51 reserve, and explicit stock reload. Every context byte is restored;
native writes stay within the bounded synthetic firing object/context. Four
listenerless post-shot negative controls retain counts and establish no shot or
chamber knowledge. No game process was opened; no native owner/cohort is emulated.

The payload emits two exact compiled registrations disabled by construction.
An AutomaticFire zero-bolt review cannot enable them. Default compiler behavior
is unchanged without --singlefire-magazine-proof. The C++ boundary test verifies
the compiled registry rejects both and an unknown-chamber Slide cannot borrow
the native Pump/Bolt readiness path. A positive chamber-evidence control isolates
that boundary from malformed owner or timing input. It passes x86/x64. Ten new
Python groups and 36 existing compiler/descriptor groups pass, including the
actual optional CLI path. Production native controls,
Gameplay and chamber/ammunition policy are unchanged.

Integration is optional and isolated: two existing tool files have hash-checked
hunks; new tools/profile/test files are additive. To include the standalone C++
test, add `include(cmake/Bc2SingleFireCandidate.cmake)` to the root CMake testing
composition. Root full builds/source pins remain separate. Do not select the
DisabledRegistry as a gameplay registry or replace the SCAR combined headers.
The tested C++ and Python targets are deterministic; installed-instruction
experiments are separate receipts and do not run during normal builds.

`selectors.json` contains exact MP443/MP443_sp rows for a bounded read-only
resource survey. Native provisioning remains unadmitted and no Harness4 enum
was allocated here. Extending its whitelist needs the same original constructor,
phase, owner and exact 14-field guards; do not reuse SCAR target ids. The corrected
constructor mapping is magazines at primary +0x180 and capacity at +0x184.

Remaining actual integration boundaries: re-evaluate/resolve the strict magazine
hand contact with shared extraction rules; review SingleFire native idle/empty
control and actual three-copy resource receipts; provide a separately measured
slide/chamber-readiness contract. Zero BoltActionTime and loaded 17 do not mean an
occupied chamber, capacity 18, slide closure or permission to fire. Existing
resource removal/original-return/refill can be reused without a per-gun consumer.

All raw negative attempts and former proof/evidence files are retained. No main
edits, game actions, injection, OS input or BF2142 changes were performed.
